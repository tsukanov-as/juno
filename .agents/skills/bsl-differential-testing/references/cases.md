# Написание сравнительных кейсов

## Формат набора

JSON в UTF-8, например:

```json
{
  "prelude": "Функция ЗначениеИТип(З)\nВозврат Новый Структура(\"type,value\",Строка(ТипЗнч(З)),XMLСтрока(З));\nКонецФункции",
  "cases": [
    {"id": "decimal-exact", "body": "Возврат ЗначениеИТип(0.1+0.2);"},
    {"id": "array-index-error", "body": "А=Новый Массив; Возврат А[0];"}
  ]
}
```

`prelude` необязателен: общие BSL-функции, без кода точки входа. `body` — тело функции
без объявления `Функция/КонецФункции`; верни наблюдение через `Возврат`. ID уникальны,
допустимы ASCII-буквы, цифры, точка, дефис и подчёркивание. Регистр ID значим.
Имена `Проба0`, `Проба1`, … и `ВыполнитьПробы` зарезервированы запускателем.

Создай набор из Python через `json.dumps(..., ensure_ascii=False, indent=2)`, если
многострочные BSL-фрагменты неудобно редактировать прямо в JSON. Файл содержит код:
проверь его перед запуском. Не вставляй в кейсы реальные учётные данные или пути
к пользовательским базам.

Один кейс должен сохранять всё существенное наблюдение. Например, для мутации
индексированной таблицы верни результаты поиска **до и после** изменения ключа,
а не только число строк в конце. Для копирования измени копию и проверь исходный
объект. Для недопустимого аргумента выполняй один потенциально ошибочный вызов:
внешняя обёртка поймает исключение и сохранит `ОписаниеОшибки()`.

## Снимки

Возвращай числа, строки, булево, массивы и структуры из этих значений. Примеры
явных наблюдений:

| Объект/семантика | Что фиксировать |
|---|---|
| Число и его тип | `ТипЗнч`, значение; для машинной десятичной формы — `XMLСтрока` |
| `Неопределено` и `Null` | Явные метки типа, если их различие существенно: JSON может свести оба к `null` |
| Дата | `XMLСтрока` и отдельно части даты, если они проверяются |
| Таблица | Имена/порядок колонок и массив строк с ячейками в порядке колонок |
| Список | Значение, представление, пометка; идентичность проверяй логическим выражением внутри кейса |
| Дерево | Значения и рекурсивные массивы детей; `Родитель/Владелец` проверяй внутри кейса |
| Regex | Значение, начальная позиция, длина, группы; отдельно отсутствие совпадения |
| Двоичные данные | Длина и hex/base64 нужных байтов |
| UUID/случайные данные | Формат, диапазон, уникальность/повторяемость по смыслу, а не случайное значение |

Не превращай всё в `Строка`: так теряются типы, а локализованное представление числа
или даты создаёт ложные расхождения. Если именно `Строка/Формат` — проверяемый API,
возвращай строку буквально и фиксируй локаль.

Компаратор читает десятичные JSON-числа через Python `Decimal`. В итоговом отчёте
такие значения показаны как `{"$decimal":"0.3"}`; исходный JSON движка сохраняется
в `<workspace>/<engine>/results.json`. Целые числа остаются целыми. Для сравнения
числового значения `1` и `1.0` равны; чтобы различать типы/форматы, верни метку/строку.

Для приблизительной математики определи нужную точность заранее и добавь отдельную
проверку погрешности. Универсальный запускатель не применяет epsilon, округление,
сортировку или Unicode-нормализацию незаметно. Для точных денежных вычислений
сравнивай точное значение.

## Отбор сценариев

Для регулярок учитывай позиции с 1, UTF-16/emoji, пустые совпадения, отсутствие
совпадения, группы, направление и синтаксис замены. Глобальные функции 1С проверяй
именно глобальными функциями. Не добавляй адаптер к классу OneScript в общий кейс:
это будет отдельная проверка сопоставления разных интерфейсов.

Для коллекций учитывай порядок, дубликаты, пустые коллекции, регистр имён,
копирование, типизированные значения, изменение схемы и инвалидирование индексов.
Графы с циклами/алиасами не отправляй напрямую в JSON: проверяй связи внутри BSL
либо используй специализированный Java-тест передачи графа.

Не объединяй в один большой набор случаи с известными зависаниями или глобальным
состоянием движка. Например, в исследовании regex платформы некорректная замена
влияла на последующие обращения с тем же шаблоном; использовались независимые
шаблоны. При подозрении на влияние запускай один ID через `--case` в новом процессе.

## Выбор контракта при расхождении

Записывай решение рядом с исследованием, например:

```json
{
  "id": "table-copy-indices",
  "selected_contract": "platform",
  "reason": "Индексы сохраняются при копировании таблицы, как в проверенной 1С",
  "platform": {"status": "ok", "value": 1},
  "oscript": {"status": "ok", "value": 0},
  "expected_juno": {"status": "ok", "value": 1}
}
```

Пример иллюстрирует структуру решения; это не автоматически загружаемый допуск.
Фактические наблюдения и версии бери из своего запуска. Универсальный запускатель
сохраняет все отличия и возвращает 1; после согласования контракта можно добавить
адресную проверку в специализированный стенд и тесты проекта.
