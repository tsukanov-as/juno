# Стенды и диагностика

Пути ниже — от корня репозитория. Полный набор регрессионных проверок:
`java Build.java test` (JDK 21+). Он проверяет самокомпиляцию, BSL-тесты и Java-тесты.

| Тема | Проверки |
|---|---|
| Коллекции, индексы, списки, деревья и циклические графы | `tests/CollectionLibraryTests.java` |
| UUID, хеширование, математика, даты, свойства | `tests/HelperLibraryTests.java`, `tests/ValueLibraryTests.java` |
| Глобальные regex-функции 1С | `tests/RegexLibraryTests.java`, `assets/regex.json` |
| Проект, ресурсы, библиотеки, JAR | `tests/ProjectTests.java` |
| Файлы, консоль, JSON | `tests/FileLibraryTests.java`, `tests/ConsoleTests.java`, `tests/JsonLibraryTests.java` |
| HTTP/TLS и процессы | `tests/HttpLibraryTests.java`, `tests/ProcessLibraryTests.java` |
| Общие кейсы для движков | `assets/collections.json`, `scripts/compare.py` |

Пути `assets/` и `scripts/` относятся к каталогу этого скилла. Справка платформы —
`shcntx_ru.hbk` в установленной версии 1С. Контракт juno описан в предметных
документах `docs/`. Записывай версии эталонов и выбранный контракт при разборе отличий;
устойчивые результаты закрепляй регрессионными тестами и документацией API.

## Механика запуска настоящей платформы

`scripts/compare.py` реализует последовательность:

```text
<platform> CREATEINFOBASE 'File="<new-temp>/db";'
<platform> DESIGNER /F <new-temp>/db /DumpConfigToFiles <new-temp>/config
  → добавить CommonModules/DifferentialProbe.xml и Module.bsl;
    зарегистрировать модуль в Configuration.xml;
    добавить вызов в Ext/ManagedApplicationModule.bsl
<platform> DESIGNER /F <new-temp>/db /LoadConfigFromFiles <new-temp>/config /UpdateDBCfg
<platform> ENTERPRISE /F <new-temp>/db /DisableStartupMessages
```

Все вызовы дополнены `/DisableStartupDialogs` и отдельным `/Out`-журналом.
Общий модуль выполняется на сервере; точка входа управляемого приложения вызывает
его, ловит аварийную ошибку в `fatal.txt` и вызывает `ЗавершитьРаботуСистемы(Ложь)`.
Не используй эти команды с существующей пользовательской базой.

Это автоматизация запуска приложения, не обещание полностью безоконного режима:
установка может потребовать графическую сессию/лицензию. Учебная установка локально
уже применялась для таких проверок. На другой машине сначала проверь простой кейс.

## Если запуск не завершился

1. Найди `workspace` в отчёте. Посмотри `records[].failure`, команды, stdout/stderr,
   `*.platform.log`, `fatal.txt`, `progress.txt` и частичный `results.json`.
2. Отсутствие полного JSON даже при коде процесса 0 означает незавершённый прогон.
   Ошибка загрузки/компиляции модуля отличается от BSL-исключения внутри кейса.
3. Повтори проблемный ID: `--case <id>`. Скрипт создаст новый процесс/каталог/базу;
   это помогает отделить проблему кейса от кеша или состояния предыдущих проб.
4. Если шаблон `Configuration.xml` другой, адаптируй создание конфигурации после
   осмотра файлов. Не подавляй проверку языка/структуры и не объявляй PASS по старому
   сохранённому эталону. Существующий адаптер проверен на русской 8.3.27.1606/macOS.

На macOS запуск из ограниченной песочницы может зависнуть уже на `CREATEINFOBASE`:
в stderr встречаются `Connection Invalid`, ошибки `NSWorkspace`/`hiservices` и
`wxRound`. Это сбой доступа приложения к системной графической сессии, а не результат
BSL-кейса. Если среда предоставляет механизм запуска вне песочницы, используй его
с обычной проверкой разрешений для конкретного тестового запуска. Без такой
возможности отметь платформу как непроверенную и продолжи доступные режимы.

Запускатель ограничивает каждую команду таймаутом и сохраняет артефакты. При таймауте
`subprocess.run` завершает и ожидает непосредственно запущенный процесс; для движков,
которые порождают отдельные процессы, проверь принадлежащие своему запуску потомки.
Не завершай чужие сеансы 1С/OneScript по имени процесса. После разбора можно удалить
свой временный каталог; автоматической очистки нет, чтобы сохранить доказательства.

Если лицензия, графическая сессия, ОС или бинарный файл недоступны, отрази это как
непроверенное покрытие. Офлайн-сравнение с ранее сохранённым `platform.json` полезно,
но в отчёте должно быть прямо названо сравнением с историческим результатом.
