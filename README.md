# juno

![juno — компилятор 1С для JVM: один JAR без платформы и базы](docs/assets/juno-hero.png)

Компилятор языка 1С для JVM. Пишешь на 1С — запускаешь везде, где есть Java:
без платформы, без базы и без установки чего-то, кроме JDK.

```sh
juno run Привет.bsl              # запустить программу
juno build Программа.bsl         # собрать программу в один jar
juno test .                      # запустить тесты, написанные на 1С
juno lint src --dialect 1c --plugin проверки  # проверить код 1С правилами, которые тоже пишутся на 1С
```

Компилятор сам написан на 1С и компилирует сам себя.

## Установка

1. Поставь OpenJDK 21 или новее:
   - Windows: `winget install Microsoft.OpenJDK.21`
   - macOS: `brew install openjdk` — в конце brew покажет команду, после которой `java` станет доступна
   - Linux: `sudo apt install openjdk-21-jdk`

   Проверь: `java -version`.
   Для сборки нужен именно JDK: команда `javac -version` тоже должна работать.

2. В корне репозитория выполни:

   ```sh
   java Build.java
   ```

   Сборка создаёт `build/juno.jar` и архив `build/juno.zip` с командами запуска,
   документацией, примерами и плагинами. Для сборки и работы сеть не нужна.

3. Распакуй `build/juno.zip` и запускай из папки `juno`:
   - macOS/Linux: `sh /путь/juno/bin/juno --help`; для команды из PATH выполни
     `chmod +x /путь/juno/bin/juno` и добавь эту bin-папку в PATH.
   - Windows PowerShell: `& 'C:\путь\juno\bin\juno.cmd' --help`;
     из распакованной папки `juno` — `.\bin\juno.cmd --help`.
     Добавь bin-папку в PATH, чтобы вызывать `juno` из других каталогов.
     Можно использовать `.\bin\juno.ps1`, который сохраняет пустые аргументы и кавычки
     также в Windows PowerShell 5.1. Если политика выполнения запрещает скрипты,
     используй `.cmd` или запусти `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\bin\juno.ps1 --help`.
   - Windows cmd.exe: `"C:\путь\juno\bin\juno.cmd" --help`.

## Локальный проект и дистрибутив

Архив `build/juno.zip` содержит runtime и команды запуска для Windows/macOS/Linux
с проверкой Java 21+. Он работает без исходников и сети.
`juno init demo` создаёт готовый проект; `juno run demo`, `juno test demo`,
`juno build demo --output app.jar` собирают его в автономное приложение.

[Manifest, локальные библиотеки, ресурсы и диагностика](docs/projects.md),
[каталог API](docs/api.md), [коллекции и индексы](docs/collections.md), [вспомогательные API](docs/helpers.md).
Пример двух приложений и одной библиотеки — `examples/проект`.

## Привет, мир

```bsl
// Привет.bsl
Функция Приветствие(Имя)
    Возврат СтрШаблон("Привет, %1!", Имя);
КонецФункции

Сообщить(Приветствие("мир"));
```

```sh
juno run Привет.bsl
```

Аргументы после имени программы попадают в `АргументыКоманднойСтроки`, а `ЗавершитьРаботу(Код)` задаёт код выхода —
как в OneScript:

```bsl
// Сумма.bsl:  juno run Сумма.bsl 2 3
Итого = 0;
Для Каждого Аргумент Из АргументыКоманднойСтроки Цикл
    Итого = Итого + Число(Аргумент);
КонецЦикла;
Сообщить(Итого);
ЗавершитьРаботу(?(Итого > 0, 0, 1));
```

## Модули — это классы

Модуль в juno устроен как модуль объекта обработки. Если ты писал обработки, ты уже всё знаешь:

| В модуле | Что это |
| --- | --- |
| `Перем Цена Экспорт;` | поле объекта, видно снаружи |
| `Перем Позиции;` | поле, видно только внутри модуля |
| `Функция Сумма() Экспорт` | метод объекта |
| операторы в конце модуля | выполняются при создании объекта |
| `Процедура ПриСозданииОбъекта(Имя, Цена)` | получает параметры `Новый ИмяМодуля(Имя, Цена)`, вызывается после операторов в конце модуля |

Объект создаётся через `Новый ИмяМодуля` или `Новый ИмяМодуля(Параметры)` — как любой другой объект.
Общий экземпляр модуля доступен через `Модули.Получить("ИмяМодуля")`:

```bsl
Лог = Модули.Получить("Логирование");
Лог.Записать("Программа запущена");
```

Первое обращение создаёт объект, следующие возвращают тот же экземпляр.
`Модули.Содержит("Логирование")` проверяет доступность модуля, а `Модули.Имена()`
перечисляет собранные модули; эти методы не запускают их код. У каждого запуска,
теста и фонового задания свои общие экземпляры. `Новый ИмяМодуля` создаёт отдельный объект.
Английские имена: `Modules.Get`, `Modules.Contains`, `Modules.Names`.
Подробности — [реестр модулей](docs/modules.md), пример — [examples/модули](examples/модули).

Программа — это папка. Главный модуль — тот, который запускаешь: его операторы в конце и есть программа.
Остальные `.bsl` рядом с ним и в подпапках — её модули. Имя модуля не включает расширение;
имена, отличающиеся только регистром, конфликтуют. Файлы с другими расширениями (в том числе `.os` из OneScript)
исходниками не считаются: перед переносом переименуйте их в `.bsl`.
Подпапка — пространство имён:
`Справочники/Товар.bsl` превращается в `Новый Справочники.Товар`.

Имена классов считаются от корня проекта — папки, где лежит файл `juno.json` (достаточно пустого `{}`).
Тогда любой модуль проекта можно запустить отдельно, например `juno run Справочники/Отладка.bsl`, —
имена классов останутся теми же. Без `juno.json` корень — папка запускаемого файла.

```bsl
// Справочники/Товар.bsl
Перем Наименование Экспорт;
Перем Цена Экспорт;

Процедура ПриСозданииОбъекта(НовоеНаименование, НоваяЦена = 0)
    Наименование = НовоеНаименование;
    Цена = НоваяЦена;
КонецПроцедуры
```

```bsl
// Корзина.bsl
Перем Позиции;

Процедура Добавить(Товар, Количество) Экспорт
    Позиции.Добавить(Новый Структура("Товар, Количество", Товар, Количество));
КонецПроцедуры

Функция Сумма() Экспорт
    Итого = 0;
    Для Каждого Позиция Из Позиции Цикл
        Итого = Итого + Позиция.Товар.Цена * Позиция.Количество;
    КонецЦикла;
    Возврат Итого;
КонецФункции

Позиции = Новый Массив; // выполнится при Новый Корзина
```

```bsl
// Программа.bsl — главный модуль
Хлеб = Новый Справочники.Товар("Хлеб", 45.50);

Покупки = Новый Корзина;
Покупки.Добавить(Хлеб, 2);
Сообщить("Итого: " + Покупки.Сумма());
```

```sh
juno run Программа.bsl
juno build Программа.bsl      # получится Программа.jar
java -jar Программа.jar       # juno для запуска уже не нужен
```

Целиком пример лежит в [examples/магазин](examples/магазин).

Под капотом это буквально так: каждый модуль компилируется ровно в один Java-класс с тем же именем.
Экспортные переменные и методы становятся public-полями и методами, числа — `BigDecimal`,
поэтому арифметика точная, как в 1С: `0.1 + 0.2 = 0.3`. `juno build` даёт обычный jar,
а скомпилированные модули можно вызывать прямо из Java.

## Тесты

Тесты пишутся тоже на 1С. Тест — экспортная процедура без параметров, имя которой начинается с `Тест`.
Тест не прошёл, если выбросил исключение. Тестовые модули удобно держать в подпапке рядом с кодом:

```bsl
// тесты/КорзинаТест.bsl
Процедура ТестСумма() Экспорт
    Хлеб = Новый Справочники.Товар("Хлеб", 45.50);
    Покупки = Новый Корзина;
    Покупки.Добавить(Хлеб, 2);
    Если Покупки.Сумма() <> 91 Тогда
        ВызватьИсключение "ожидалось 91, получено " + Покупки.Сумма();
    КонецЕсли;
КонецПроцедуры
```

```
$ juno test examples/магазин
Тестов: 2, упало: 0
```

`juno test папка` компилирует все модули папки и подпапок и вызывает тесты каждого модуля;
каждый тест получает новый объект своего модуля. Упавший тест печатается со строкой, где он упал.

## Проверка кода

`juno lint` проверяет синтаксис и семантику кода juno, включая имена типов и модулей.
Для кода платформы 1С укажи `--dialect 1c`: он проверяет синтаксис платформы без проверки типов juno.
Дополнительные правила пишутся плагинами — обычными модулями на 1С.

```sh
juno lint Модуль.bsl --dialect 1c                          # только синтаксис 1С
juno lint папка/с/выгрузкой --dialect 1c --plugin проверки  # с плагинами из папки
juno lint src --dialect 1c --plugin МояПроверка.bsl         # с одним плагином
```

В папке [plugins](plugins) лежат примеры плагинов — бери как есть или переделывай под себя:

| Плагин | Что находит |
| --- | --- |
| `ЗапросВЦикле.bsl` | запрос к базе выполняется на каждой итерации цикла |
| `ПодавлениеИсключений.bsl` | блок `Исключение` глушит ошибку и даже не смотрит, что случилось |
| `МодальныеВызовы.bsl` | `Вопрос`, `Предупреждение`, `ВвестиЧисло` и другие — и чем их заменить |

```
$ juno lint examples/проверка --plugin plugins --dialect 1c
examples/проверка/Модуль.bsl:9:13: Запрос выполняется в цикле [ЗапросВЦикле]
examples/проверка/Модуль.bsl:16:2: Пустой блок Исключение: ошибка теряется [ПодавлениеИсключений]
examples/проверка/Модуль.bsl:21:7: Модальный вызов Вопрос(): используйте ВопросАсинх [МодальныеВызовы]
examples/проверка/Модуль.bsl:24:3: Ошибка теряется: блок Исключение не использует ни ВызватьИсключение, ни ИнформацияОбОшибке(), ни ОписаниеОшибки() [ПодавлениеИсключений]
Файлов: 1, замечаний: 4, файлов с ошибками: 0
```

Как написать свой плагин — в [plugins/README.md](plugins/README.md).

Чтобы не перечислять плагины каждый раз, запиши их в `juno.json` в корне проекта и закоммить его вместе с кодом:

```json
{
  "plugins": ["проверки"],
  "params": {"ПодавлениеИсключений.bsl": {"Обработчики": "ОбщегоНазначения.ЗаписатьОшибку"}}
}
```

Здесь `проверки` — папка проекта с плагинами. Тогда достаточно `juno lint src --dialect 1c`.
`juno.json` ищется в проверяемой папке и выше, до корня git-репозитория; пути в нём — относительно него самого.
Если указать `--plugin` или `--params`, `juno.json` не читается, а `--config файл` задаёт настройки явно.

Для больших выгрузок пригодятся `--jobs 4` — проверять файлы параллельно — и отчёт для других программ (CI, скриптов):
`--format json --output отчет.json` — массив, по объекту на каждый файл и итоговый объект,
`--format jsonl --output отчет.jsonl` — те же объекты в формате JSON Lines, по одному на строку.
Синтаксис juno (`Новый Справочники.Товар`) разрешён по умолчанию; `--dialect 1c` оставляет только синтаксис платформы.
Код выхода: 0 — замечаний нет, 1 — есть замечания, 2 — неверный вызов, 3 — сбой. Все опции: `juno help`.

Парсер доступен и из своей программы: `Новый Парсер`, затем `Разобрать(Текст)` возвращает синтаксическое дерево —
то самое, которое обходят плагины.

## Что умеет

Вычислительную часть языка 1С: переменные, процедуры и функции, циклы и переходы, исключения,
`Массив`, `Структура`, `Соответствие`, `ТаблицаЗначений`, строки, даты, точную десятичную арифметику,
фоновые задания, `#Если` (символы задаются через `--define`), `АргументыКоманднойСтроки` и `ЗавершитьРаботу`.

Базовые даты, явный `Формат` и машинные XML-преобразования описаны в
[поддерживаемом поднаборе библиотеки значений](docs/values.md).
Рабочий пример: `juno run examples/значения/Программа.bsl`.
Файлы, кодировки, EOF, закрытие ресурсов и потоки описаны в [файловой библиотеке](docs/files.md);
пример chunks: `juno run examples/файлы/Программа.bsl источник.bin копия.bin`.
[Консоль и окружение](docs/console.md) позволяют писать фильтры stdin/stdout;
пример: `printf 'Привет\n' | java -jar build/juno.jar run examples/консоль/Программа.bsl`.
[Глобальные регулярные выражения 1С](docs/regex.md) находят совпадения и группы, заменяют текст
и проверяют всю строку; [пример](examples/регулярные/Программа.bsl) извлекает и нормализует даты.
[Публичный JSON](docs/json.md) поддерживает точные числа, файлы и потоковые tokens;
пример конфигурации и JSONL: `examples/json/Программа.bsl`.
[HTTP/HTTPS](docs/http.md) поддерживает REST JSON, файлы, явные proxy и TLS с проверкой сертификатов;
[пример](examples/http/Программа.bsl) берёт Bearer token из среды и сохраняет ответ.
[Процессы](docs/processes.md) запускают инструменты с отдельными stdout/stderr, stdin и отменой;
[пример автоматизации](examples/процессы/Программа.bsl) передаёт файл и сохраняет outputs chunks.
[MCP-сервер](examples/mcp/README.md) показывает stdio JSON-RPC, инициализацию и два инструмента;
его можно запустить через juno или собрать в самостоятельный JAR для MCP-клиента.

Нет запросов, форм, метаданных и базы данных. `Асинх` и `Ждать` не компилируются.

## Как устроено

```
src/Parser.bsl     парсер: текст модуля → синтаксическое дерево
src/Compiler.bsl   компилятор: дерево → байткод JVM
src/juno/          командная строка и рантайм на Java
plugins/           примеры плагинов и руководство по их написанию
examples/          примеры
tests/             тесты на 1С (juno test tests) и тест командной строки на Java
bootstrap/         seed.jar — уже собранный компилятор, им собирается текущий
Build.java         сборка
```

Компилятор написан на 1С, поэтому собрать его можно только компилятором.
`Build.java` берёт готовый из `bootstrap/seed.jar` и компилирует им исходники.
Если исходники менялись, новый компилятор компилирует сам себя ещё раз.

## Разработка

```sh
java Build.java test    # собрать, проверить, что компилятор воспроизводит себя, и прогнать все тесты
java Build.java seed    # после изменений в Parser.bsl или Compiler.bsl: тесты и новый seed.jar
```

### Скиллы для агентов

Скиллы лежат в `.agents/skills/` (Codex). Для Claude Code `.claude/skills` — символическая
ссылка на этот каталог. На Windows git по умолчанию не создаёт символические ссылки:
включи режим разработчика и клонируй с `git clone -c core.symlinks=true`
(в уже клонированном репозитории: `git config core.symlinks true`, удали файл
`.claude/skills` и выполни `git checkout -- .claude/skills`). Без ссылки Claude Code скиллы не увидит, остальное работает.
