# Файлы, текст и байты

Набор работает на JDK 21 без сторонних библиотек и предоставляет описанный поднабор API OneScript 2.2.1.
Эмуляция .NET и поддержка устройств ОС не входят в этот API.

## Контекст и закрытие

Все операции с относительными путями используют **виртуальный текущий каталог** приложения.
`ТекущийКаталог()`/`CurrentDirectory()` и `УстановитьТекущийКаталог(Путь)`/`SetCurrentDirectory`
не меняют `user.dir` или каталог нативного процесса JVM. Новый вызов CLI получает отдельный
контекст; `run`, автономный JAR и каждый BSL-тест владеют своими ресурсами. Анализ каждого
файла lint, включая `--jobs 1`, получает отдельный снимок каталога и среды.

Фоновое задание получает **снимок при запуске**: cwd, environment и host streams.
Изменения каталога/среды одного задания не меняют родителя и соседей. Открытые читатели,
писатели, потоки и изменяемые двоичные буферы запрещены в параметрах и результатах заданий.
Метаданные `Файл`, двоичные значения и значения перечислений можно передавать.

Успех, исключение и отмена закрывают принадлежащие scope ресурсы. Отмена прерывает worker
и закрывает underlying file channel без ожидания монитора reader/writer. I/O close выполняется
вне монитора менеджера заданий; регистрация одновременно с отменой немедленно закрывает
новый handle. Cleanup продолжает обход после ошибки отдельного ресурса, сохраняя ошибки.
Закрытие writer при обычном выходе сбрасывает буфер; отмена может потерять незаписанный хвост.
После прерванной записи выходной файл может быть частичным.

Явное `Закрыть()`/`Close()` обязательно в обычном коде и идемпотентно. Контекст — страховка
на выходе, а не замена управлению временем жизни. BSL не имеет `finally`; используйте шаблон:

```bsl
Ч = Новый ЧтениеТекста(Путь);
Попытка
    Пока Истина Цикл
        СтрокаФайла = Ч.ПрочитатьСтроку();
        Если СтрокаФайла = Неопределено Тогда Прервать; КонецЕсли;
        // обработка
    КонецЦикла;
Исключение
    Ч.Закрыть(); ВызватьИсключение;
КонецПопытки;
Ч.Закрыть();
```

Java host может явно создать `ApplicationContext(Path, Map<String,String>, InputStream,
OutputStream, OutputStream)` и войти через `Execution.withContext(context)`; оба объекта
используются в try-with-resources. Перегрузки `BackgroundJobs` принимают готовый context.
Вне явного scope файловый API Java embedding выдаёт понятную ошибку; скрытого глобального
владельца нет. `Execution.messages()` меняет только сообщения и не закрывает ресурсы.
Host stdin/stdout/stderr контекст **не закрывает**. Java host управляет виртуальной средой через
`environment()`/`environment(name,value)`. В BSL доступны `ПолучитьПеременнуюСреды`,
`УстановитьПеременнуюСреды`, `ПеременныеСреды` и глобальное свойство `Консоль`;
их контракт описан в [консоли и окружении](console.md).

## Файл и пути

`Новый Файл(Путь)` / `New File(Path)` хранит лексическое имя. Для относительного имени
`ПолноеИмя` и операции вычисляются заново от текущего cwd, как в проверенном OneScript.
Если нужен стабильный адрес, сохраните абсолютное `ПолноеИмя`.

| RU | English | Контракт |
| --- | --- | --- |
| `Имя`, `ИмяБезРасширения`, `Расширение` | `Name`, `BaseName`, `Extension` | свойства; расширение включает точку |
| `Путь`, `ПолноеИмя` | `Path`, `FullName` | исходная папка с разделителем / абсолютный нормализованный путь |
| `Существует()` | `Exist()` | false для отсутствующего пути; dangling link существует как запись |
| `ЭтоФайл()`, `ЭтоКаталог()` | `IsFile()`, `IsDirectory()` | проверяют target; отсутствие target — ошибка |
| `Размер()` | `Size()` | байты обычного файла, каталог/устройство отвергаются |
| `ПолучитьВремяИзменения()`, `УстановитьВремяИзменения(Дата)` | `GetModificationTime`, `SetModificationTime` | локальные календарные поля системного timezone, точность зависит от FS |
| `ПолучитьТолькоЧтение()`, `УстановитьТолькоЧтение(Булево)` | `GetReadOnly`, `SetReadOnly` | DOS readonly на Windows; биты записи POSIX на Unix |

На Unix установка readonly снимает все биты записи, снятие readonly добавляет owner-write.
`NameWithoutExtension` дополнительно принят как alias juno. У `a.txt` свойство `Путь` пустое.
Dangling link: `Существует()` true, чтение свойств target вроде `ЭтоФайл()` — ошибка;
это отличается от наблюдённого OneScript. Символические ссылки на обычные файлы поддержаны.
Открытие каталогов, FIFO и устройств как потоков/текста/двоичных файлов отвергается.
Это позволяет отменять поддерживаемое file-channel I/O, не зависая при открытии FIFO.

| Глобальная функция | English | Аргументы |
| --- | --- | --- |
| `НайтиФайлы` | `FindFiles` | путь, маска необязательно, рекурсия=false |
| `КопироватьФайл` | `FileCopy`, `CopyFile` | источник, приёмник; обычные файлы, перезапись разрешена |
| `ПереместитьФайл` | `MoveFile` | источник, приёмник; существующий приёмник — ошибка |
| `УдалитьФайлы` | `DeleteFiles` | путь, необязательная маска |
| `СоздатьКаталог` | `CreateDirectory` | путь; создаёт родителей, существующая папка допустима |
| `ОбъединитьПути` | `CombinePath` | 1–16 частей; абсолютная часть заменяет предыдущие |
| `ПолучитьРазделительПути` | `GetPathSeparator` | без аргументов |
| `КаталогВременныхФайлов` | `TempFilesDir` | без аргументов, с завершающим разделителем |
| `ПолучитьИмяВременногоФайла` | `GetTempFileName` | необязательное расширение, default `tmp` |

`ОбъединитьПути` возвращает путь, не открывает его и не превращает относительные части
в абсолютные. `ПолучитьИмяВременногоФайла` выдаёт уникальное предлагаемое имя,
**не создавая файл**. Оно не резервирует имя. Для атомарного создания используйте
`РежимОткрытияФайла.СоздатьНовый`; внутренние Java-temporary файлы создаются атомарно.
Для копирования принимаются оба EN-имени: `FileCopy`, используемое в
[официальном примере 1С](https://1c-dn.com/blog/customization-of-1c-enterprise-platform-built-in-data-processors/),
и подтверждённое пробой OneScript `CopyFile`; сигнатура и реализация общие.

Поиск без маски возвращает сам существующий путь как единственный `Файл`.
Явная пустая маска, `*` и `*.*` перечисляют всё, включая папки и hidden entries.
`?` допускает отсутствие символа перед точкой/концом, поэтому `?.*` совпадает с `.hidden`.
Регистр игнорируется; результаты отсортированы по абсолютному пути для воспроизводимости.
Рекурсия обходит подпапки, но **не следует directory symlinks**, поэтому link cycles не обходятся.
Отсутствующая папка даёт пустой массив; маска с путём и маска при path, который является файлом,
дают ошибку. Последний случай строже OneScript (там пустой результат).

Удаление без маски рекурсивно удаляет дерево; symlink удаляется как ссылка, target не обходится.
Удаление отсутствующего пути успешно. С маской выбираются только непосредственные дети;
совпавшие каталоги удаляются рекурсивно. Ошибки прав/FS сообщаются с причиной без rollback.
Потоковая `КопироватьФайл` проверяет отмену и не загружает файл целиком в память.
Копирование файла самого в себя (включая alias того же inode) ничего не меняет.
Копирование сохраняет mtime и POSIX permissions (включая executable bits), на Windows — DOS readonly.
ACL, owner/group identity и xattrs не копируются; ошибка применения поддерживаемых атрибутов сообщается явно.
Перемещение regular file между разными filesystem выполняет отменяемое копирование с CreateNew,
затем удаляет источник; до успешного окончания копии источник сохраняется.
Перенос каталогов между filesystem не поддерживается. Метаданные FS могут изменяться другими процессами;
операции не дают транзакционной гарантии против внешних гонок или ошибок удаления.

## Текст и кодировки

`КодировкаТекста` / `TextEncoding` — настоящее перечисление; тип разрешается до первого
открытия ресурса. Значения: `Системная`/`System`, `ANSI`, `OEM`, `UTF16`, `UTF8`,
`UTF8БезBOM`/`UTF8NoBOM`. Можно передавать строковое имя JDK charset.

| Кодировка | Charset | BOM writer |
| --- | --- | --- |
| default, `UTF8`, `Системная`, `"UTF-8"` | UTF-8 | EF BB BF |
| `UTF8БезBOM` | UTF-8 | нет |
| `UTF16`, `"UTF-16"`, `"UTF-16LE"` | UTF-16LE | FF FE |
| `"UTF-16BE"` | UTF-16BE | FE FF |
| `ANSI` | windows-1251 | нет |
| `OEM` | IBM866 | нет |

Выбор `Системная` фиксирован по сохранённым байтам 1С 8.3.27: UTF-8 **с BOM**.
Наблюдённый OneScript 2.2.1 пишет System без BOM — осознанное отличие.
При записи строка→двоичные данные BOM по умолчанию отсутствует; третий
параметр `ПолучитьДвоичныеДанныеИзСтроки` включает его явно.
В файловых reader/writer неизвестные charset, повреждённые byte sequences,
непарные суррогаты и непредставимые символы дают ошибку (строгий REPORT).
Отдельный конвертер `ПолучитьСтрокуИзДвоичныхДанных` заменяет повреждения на U+FFFD,
как в проверенной 1С.

`Новый ЗаписьТекста(Файл?, Кодировка?, РазделительСтрок?, Дописывать=false)` / `TextWriter`.
Без файла создаётся неоткрытый объект; `Открыть`/`Open` принимает те же 1–4 аргумента.
`Записать(Текст)` / `Write` заменяет каждый LF на CRLF (существующий CR остаётся).
`ЗаписатьСтроку(Текст="", Разделитель?)` / `WriteLine` выполняет ту же замену в тексте
и добавляет разделитель буквально, по умолчанию CRLF.
При дописывании в непустой файл второй BOM не пишется. В пустой файл BOM записывается.
Автоматическая проверка совместимости существующей кодировки при append не выполняется;
кодировка должна совпадать. Дополнительные параметры преобразования строк не поддерживаются.

`Новый ЧтениеТекста(Файл?, Кодировка?, РазделительСтрок?)` / `TextReader`, `Открыть`/`Open` — 1–3 аргумента.
BOM UTF-8/UTF-16 распознаётся и переопределяет явно заданную кодировку. UTF-32 BOM отвергается.
Без BOM default UTF-8. CRLF и одиночный CR нормализуются в LF.
`Прочитать(Количество?)` / `Read` читает указанное число UTF-16 units или весь остаток;
`ПрочитатьСтроку(Разделитель?)` / `ReadLine` читает до разделителя (default LF), не включая его.
Custom separator применяется после нормализации: явный CRLF не совпадёт с уже преобразованным LF.
EOF — `Неопределено`; пустая строка — `""`; `Прочитать(0)` возвращает `""`.
Закрытый объект можно снова открыть, если владеющий scope ещё жив.

`ТекстовыйДокумент` / `TextDocument` хранит весь текст в памяти:
`Прочитать/Read(Файл,Кодировка?)`, `Записать/Write(Файл,Кодировка?)`, `УстановитьТекст/SetText`,
`ПолучитьТекст/GetText`, `КоличествоСтрок/LineCount`, `ПолучитьСтроку/GetLine`,
`ДобавитьСтроку/AddLine`, `ВставитьСтроку/InsertLine`, `ЗаменитьСтроку/ReplaceLine`,
`УдалитьСтроку/DeleteLine`, `Очистить/Clear`. Нумерация с 1; неверный номер — ошибка.
Новый документ содержит 0 строк. Текст нормализуется в LF; `ПолучитьТекст` сохраняет
наличие завершающего перевода строки после `УстановитьТекст`. `ДобавитьСтроку` добавляет LF.
Он не предназначен для больших файлов; используйте reader chunks или потоки.

## Двоичные значения и потоки

`Новый ДвоичныеДанные(Файл)` / `BinaryData` загружает файл целиком;
`Размер/Size()` возвращает число байтов, `Записать/Write(Файл)` перезаписывает файл.
Это API значений в памяти, в отличие от потоков.

`ПолучитьДвоичныеДанныеИзСтроки/GetBinaryDataFromString` и
`ПолучитьСтрокуИзДвоичныхДанных/GetStringFromBinaryData` принимают значение и необязательную кодировку.
`ПолучитьДвоичныеДанныеИзСтроки` принимает третий булев параметр добавления BOM
(по умолчанию Ложь). При чтении двоичного значения BOM снимается и определяет кодировку.
`Base64Строка/Base64String` не вставляет переносы;
`ПолучитьBase64СтрокуИзДвоичныхДанных/GetBase64StringFromBinaryData` вставляет CRLF каждые 76 символов.
`Base64Значение/Base64Value` читает полный префикс до недопустимого символа;
неполная группа даёт `Неопределено`, пустой префикс — пустые данные.
`ПолучитьДвоичныеДанныеИзBase64Строки/GetBinaryDataFromBase64String` игнорирует
только пробел/таб/CR/LF, требует padding и отвергает посторонний мусор.
`ПолучитьHexСтрокуИзДвоичныхДанных/GetHexStringFromBinaryData` выдаёт uppercase без пробелов;
`ПолучитьДвоичныеДанныеИзHexСтроки/GetBinaryDataFromHexString` разрешает пробел/таб/CR/LF.

`Новый БуферДвоичныхДанных(Размер, ПорядокБайтов=LittleEndian)` / `BinaryDataBuffer`:
свойства `Размер/Size`, `ПорядокБайтов/ByteOrder`, `ТолькоЧтение/ReadOnly` (false);
индексы с 0, байты 0–255; `Получить/Get`, `Установить/Set`, `Скопировать/Copy`.
Свойства read-only; прочие операции над многобайтными числами не поддерживаются.

`Новый ФайловыйПоток(Файл, Режим, Доступ?)` / `FileStream` и
`Новый ПотокВПамяти(Емкость=0)` / `MemoryStream`. Емкость не изменяет длину.
Базовый `Поток/Stream` не создаётся непосредственно. Размер memory stream/buffer ограничен JVM int;
длина и позиции file stream — long. Неподдерживаемые constructor arguments отвергаются.

Режимы `РежимОткрытияФайла/FileOpenMode`:
`Открыть/Open`, `ОткрытьИлиСоздать/OpenOrCreate`, `Создать/Create` (обрезает),
`СоздатьНовый/CreateNew` (ошибка при наличии), `Обрезать/Truncate` (требует существующий),
`Дописать/Append`. Доступ `ДоступКФайлу/FileAccess`: `Чтение/Read`, `Запись/Write`,
`ЧтениеИЗапись/ReadAndWrite`; default ReadAndWrite, для Append — Write.
Append допускает только Write и запрещает seek/setsize ниже **исходного** EOF.
OpenOrCreate+Read создаёт отсутствующий файл и затем открывает для чтения.

| Методы потока | English | Контракт |
| --- | --- | --- |
| `Прочитать(Буфер,Смещение,Количество)` | `Read` | число прочитанных байтов, EOF=0 |
| `Записать(Буфер,Смещение,Количество)` | `Write` | записывает весь выбранный диапазон |
| `ТекущаяПозиция()` | `CurrentPosition` | текущая абсолютная позиция |
| `Размер()` | `Size` | текущая длина |
| `Перейти(Смещение,Относительно=Начало)` | `Seek` | новая позиция; отрицательная — ошибка |
| `УстановитьРазмер(Размер)` | `SetSize` | расширение заполняет нулями, сокращение обрезает; позиция ограничивается новой длиной |
| `СброситьБуферы()` | `Flush` | file channel force для writable потока |
| `Закрыть()` | `Close` | идемпотентное закрытие |
| `ЗакрытьИПолучитьДвоичныеДанные()` | `CloseAndGetBinaryData` | только memory stream; отдельное byte value |

Свойства: `ДоступноЧтение/CanRead`, `ДоступнаЗапись/CanWrite`, `ДоступноИзменениеПозиции/CanSeek`.
Перечисление `ПозицияВПотоке/PositionInStream`: `Начало/Begin`, `Текущая/Current`, `Конец/End`.
`StreamPosition` также принят как alias. `ПорядокБайтов/ByteOrder`: `BigEndian`, `LittleEndian`.

[Пример копирования chunks и текстового отчёта](../examples/файлы/Программа.bsl) открывает
источник/приёмник, копирует по 64 KiB и явно закрывает ресурсы на обеих ветках.
Приёмник примера создаётся с CreateNew: существующий выходной файл не перезаписывается.
Интеграционный тест копирует 64 MiB+1 под `-Xmx32m`, сравнивая SHA256.
Он проверяет ограниченную память и неполный последний chunk; reader/text document whole-read
и двоичные значения целиком не обещают ограниченного потребления памяти.


## ДвоичныеДанные → поток

`ДвоичныеДанные.Записать(Приемник)` / `BinaryData.Write(Target)` принимает путь
либо открытый FileStream, MemoryStream или стандартный output/error Stream.
Байты записываются **с текущей позиции**, без seek, BOM, перекодирования и закрытия приёмника.
После успешного вызова позиция увеличивается на число записанных байтов; приёмник остаётся
принадлежащим своему scope. Readonly/input/closed потоки дают ошибку, включая пустые данные.
В память не копируется дополнительное двоичное значение; передача идёт блоками до 64 КиБ
с проверками отмены. Само ДвоичныеДанные уже хранит весь payload в памяти.

Пустая запись сохраняет текущую позицию. Если MemoryStream был перемещён **за EOF**,
даже запись нуля байтов расширяет его до этой позиции с нулями — это подтверждено в OS2.2.1.
В пределах имеющейся длины пустая запись не меняет содержимое/размер.
Для host stdout/stderr проверяется PrintStream.checkError (broken pipe — ошибка).
Закрытие стандартной обёртки не закрывает host stream: новую обёртку можно открыть снова.
Ограничения отмены произвольного блокирующего host OutputStream остаются
[описанными для Console](console.md).

Переносимый явный UTF-8 вывод текста в stderr:

```bsl
ПотокОшибок = Консоль.ОткрытьСтандартныйПотокОшибок();
Попытка
    ПолучитьДвоичныеДанныеИзСтроки("Ошибка" + Символы.ПС, КодировкаТекста.UTF8).Записать(ПотокОшибок);
Исключение
    ПотокОшибок.Закрыть(); ВызватьИсключение;
КонецПопытки;
ПотокОшибок.Закрыть();
```

`GetBinaryDataFromString` по умолчанию не добавляет BOM; здесь EOL — явный LF, независимо от системы
