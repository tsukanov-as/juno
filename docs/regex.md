# Глобальные регулярные выражения

Контракт сверён со справкой `shcntx_ru.hbk` и исполнением проб на 1С 8.3.27.1606
с русским языком конфигурации.
OneScript 2.2.1 не является эталоном этих globals; объект `РегулярноеВыражение` не поддерживается.

| RU / EN | Аргументы |
|---|---|
| СтрНайтиПоРегулярномуВыражению / StrFindByRegularExpression | `(Строка, Шаблон[, Направление=НаправлениеПоиска.СНачала, Начало, Вхождение=1, ИгнорироватьРегистр=Ложь, МногострочныйПоиск=Ложь])` |
| СтрНайтиВсеПоРегулярномуВыражению / StrFindAllByRegularExpression | `(Строка, Шаблон[, ИгнорироватьРегистр=Ложь, МногострочныйПоиск=Ложь])` |
| СтрЗаменитьПоРегулярномуВыражению / StrReplaceByRegularExpression | `(Строка, Шаблон, Замена[, ИгнорироватьРегистр=Ложь, МногострочныйПоиск=Ложь])` |
| СтрПодобнаПоРегулярномуВыражению / StrLikeByRegularExpression | `(Строка, Шаблон[, ИгнорироватьРегистр=Ложь, МногострочныйПоиск=Ложь])` |

Имена RU/EN регистронезависимы. Строка/шаблон/замена требуют строковых значений, флаги —
Булево. Пропущенный необязательный аргумент или `Неопределено` выбирает default.
У Find Начало по умолчанию 1 вперёд и длина строки назад; Начало/Вхождение требуют числа,
дробная часть отбрасывается к нулю. При непустом поиске Начало должно быть от 1 до длины
строки, Вхождение ≥1; иначе ошибка. Для пустой строки/шаблона и
отсутствующего совпадения возвращается пустой результат. Позиции и длины считаются в единицах
UTF-16, с 1; поэтому в `x😀42` цифры начинаются с 4.

Find возвращает `РезультатПоискаПоРегулярномуВыражению` /
`ResultOfSearchByRegularExpression`, All — обычный Массив таких объектов. Свойства доступны
только для чтения: `НачальнаяПозиция/StartIndex`, `Длина/Length`, `Значение/Value`.
Отсутствие совпадения: 0, 0, `""`; `ПолучитьГруппы()/GetGroups()` возвращает пустой массив.
Группы нумеруются по открывающим скобкам: элемент 0 массива — capture $1; $0 в массив не входит.
Группа имеет тип `ГруппаРезультатаПоискаПоРегулярномуВыражению` /
`ResultOfSearchByRegularExpressionGroup` и те же три readonly-свойства. Её позиции также
абсолютны относительно исходной строки. Неучаствовавшая optional-группа имеет 0/0/`""`;
участвовавшая пустая группа сохраняет реальную позицию при длине 0.
GetGroups каждый раз возвращает новый изменяемый массив; изменение массива не меняет результат.
Сами результаты и группы неизменяемы и допускают передачу в фоновое задание.

Find/All с пустым **шаблоном** возвращают отсутствие совпадений, как 1С; Like(`"", ""`) — Истина.
Для пустой исходной строки Find/All также возвращают отсутствие совпадений без компиляции
шаблона и проверки необязательных аргументов, поэтому All(`"", "["`) возвращает пустой массив, а Like(`"", "["`) сообщает ошибку.
Непустой шаблон, допускающий нулевую длину, например `a*` или `(?=)`, даёт пустые совпадения,
включая конец текста. После пустого совпадения прямой поиск и замена продвигаются на Unicode
code point, не зацикливаются и не разрезают корректную суррогатную пару. All и последовательный поиск вперёд
дают неперекрывающиеся вхождения; обратный Find проверяет возможные начала справа налево.
Обратные последовательные совпадения также не перекрываются: последующее совпадение должно
закончиться не позже начала предыдущего. Квантификаторы продолжают видеть полный текст;
проверка не обрезает длинное жадное совпадение до предыдущей границы. Поэтому обратный поиск
`aaaa` по `a+` даёт сначала `a` в позиции 4, а второго вхождения нет. Явная начальная позиция
обратного поиска может находиться между UTF-16 суррогатами, как в целевой платформе.
Начало ограничивает начало совпадения, а не его конец: Find(`"abc","bc",СКонца,2`) находит `bc`.
Lookbehind и якоря продолжают видеть исходный текст при заданном Начало.

Like проверяет **всю** строку. Флаг МногострочныйПоиск меняет `^`/`$` на границы строк;
он не включает dot-all. Явный `(?s)` позволяет точке совпасть с переводом строки.

```bsl
Результат = СтрНайтиПоРегулярномуВыражению("Код A-42", "([A-Z])-(\d+)");
Сообщить(Результат.Значение); // A-42
Сообщить(Результат.GetGroups()[1].Value); // 42
Текст = СтрЗаменитьПоРегулярномуВыражению("2024-02-29", "(\d{4})-(\d{2})-(\d{2})", "$3.$2.$1");
Сообщить(Текст); // 29.02.2024
```

## Замена

Заменяются все неперекрывающиеся совпадения, включая допустимое пустое в конце.
В отличие от Find/All, пустой шаблон в Replace работает: Replace(`"abc","","X"`) → `"XaXbXcX"`.
Пустой исходник также допускает совпадение: Replace(`"","a*","X"`) → `"X"`.
`$0` означает всё совпадение, `$1..$n` — capture-группы. Берётся наиболее длинный допустимый
номер: с одной группой `$12` означает `$1` и литерал `2`. `$0` потребляет ровно одну цифру:
`$01` означает всё совпадение и литерал `1`, `$000` — всё совпадение и `00`. Неучаствовавшая группа подставляет `""`.
Обратный слеш экранирует следующий символ: `\$1` — буквальный `$1`, `\n` — буква `n`.
Это строка замены, не BSL-escape: обратный слеш в BSL-строке сам по себе сохраняется.
Доллар без следующей цифры — литерал, поэтому `$$` остаётся `$$`, `${1}` остаётся `${1}`.

Несуществующий номер группы и конечный обратный слеш проверяются **до поиска** и вызывают ошибку,
включая случай отсутствия совпадений. Это намеренное расхождение с наблюдаемой 1С 8.3.27.1606:
платформа возвращает пустую строку, даже если исходник не содержал совпадений.
Juno сообщает причину вместо потери текста. Кэш juno хранит только неизменяемые Pattern;
ошибочная замена не влияет на следующий вызов с тем же шаблоном.

## Движок, Unicode и пределы

Реализация использует JDK 21 `java.util.regex.Pattern`, без внешних JAR. Полная эквивалентность
ICU, используемому 1С, не заявляется. Подтверждены обычные группы/квантификаторы/альтернативы,
lookahead/lookbehind, Unicode `\w`/`\d`/`\s`, якоря и простое RU/EN игнорирование регистра.
Всегда включён `UNICODE_CHARACTER_CLASS` (он подразумевает `UNICODE_CASE`), а при запросе —
`CASE_INSENSITIVE` и `MULTILINE`. Новые символы Unicode и наборы свойств зависят от JDK21.

Именованные capture-группы отвергаются: целевая установленная платформа не принимает
`(?<part>a)`. Пронумерованные группы и ссылки `$n` — поддерживаемый контракт.
Экранированный буквальный текст вида `\Q(?<part>a)\E` не считается именованной группой.
JDK использует простое case folding: `Like("ß","ss",Истина)` — Ложь; в целевой 1С — Истина.
Многосимвольное ICU folding, ICU-specific UnicodeSet/`(?w)` и все различия Unicode word boundaries
не эмулируются. Поведение сложных конструкций, особенно `\G` при обратном поиске, не входит в
подтверждённый общий поднабор; для них нужен отдельный зонд. Синтаксис JDK, которому нет аналога
в ICU, не превращает API в обещание совместимости этих диалектов.

Кэш содержит максимум 64 успешно скомпилированных шаблона (LRU); ключ включает строку и флаги.
Pattern разделяется между потоками, Matcher/входные строки/результаты в кэше не хранятся.
Максимумы на вызов: 8192 UTF-16 единицы компилируемого шаблона, 16 Mi UTF-16 единиц исходника/замены/итоговой
строки, 256 capture-групп, 100 000 совпадений. При материализации результатов суммарно допускается
100 000 объектов совпадений и групп и 16 Mi UTF-16 единиц их текста; вложенные группы учитываются
отдельно, поэтому с большим числом групп предел достигается раньше.

Дополнительно ограничена работа matcher и разбора замены: максимум
`max(10 000 000, 64 × (длина исходника + длина замены))` условных шагов; для поиска длина замены 0.
Чтения символов matcher и проверка каждой начальной позиции обратного поиска считаются шагами.
Проверка отмены выполняется во время работы, включая обратный поиск и замену. Превышение лимита,
невалидный шаблон и переполнение стека дают BSL-ошибку с сохранением доступной JVM-причины;
ошибка шаблона содержит позицию UTF-16. JDK иногда сам оборачивает compiler StackOverflowError
в PatternSyntaxException — именно эта доступная причина сохраняется.

Это ограничения работы и памяти, **не гарантия времени исполнения** Java Pattern. Нет фонового
потока, продолжающего вычисление после фиктивного timeout. Линейный поиск по всему допустимому
16 Mi исходнику проверяется отдельно от патологического backtracking; малый стек, отмена,
лимиты кэша/результатов/замены и CLI file/line/cause покрыты тестами.

Рабочий пример: `juno run examples/регулярные/Программа.bsl`. Независимый корпус из 89
платформенных проб проверяет globals как через CLI, так и через автономный JAR из постороннего cwd.

Источники движка: [JDK21 Pattern](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/regex/Pattern.html),
[различия ICU с Java](https://unicode-org.github.io/icu/userguide/strings/regexp.html#differences-with-java-regular-expressions).
