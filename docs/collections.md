# Коллекции значений

Вычислительные операции `ТаблицаЗначений/ValueTable`, `СписокЗначений/ValueList` и
`ДеревоЗначений/ValueTree` работают без платформы и внешних JAR. Конструкторы не принимают
аргументов. Имена типов, методов и свойств RU/EN регистронезависимы; индексы начинаются с 0.
Числовой индекс/смещение отбрасывает дробную часть к нулю; выход за границы сообщает BSL-ошибку.
`Сдвинуть/Move` переставляет элемент внутри его коллекции, не зацикливает смещение.
Методы, изменяющие коллекцию без возвращаемого результата, возвращают Неопределено.

Сигнатуры и различия поведения описаны относительно 1С **8.3.27.1606**
и OneScript **2.2.1**. Формы, диалоги и визуальные элементы платформы не поддерживаются.

## Таблица и колонки

У таблицы readonly-свойства `Колонки/Columns`, `Индексы/Indexes`. Сама таблица перебирает
строки; строка перебирает значения в текущем порядке колонок. `Т[0]`, `Т.Получить(0)/Get(0)`
дают ту же строку. Ячейка доступна как `Строка.Код`, `Строка["Код"]`, `Строка[0]` или
`Строка[Колонка]`; `Получить/Get(Индекс)` и `Установить/Set(Индекс, Значение)` используют
числовой индекс. `Строка.Владелец()/Owner()` возвращает таблицу.

| RU / EN | Аргументы и результат |
|---|---|
| Добавить / Add, Вставить / Insert | `()` / `(Индекс)` → новая строка |
| Получить / Get, Количество / Count, Индекс / IndexOf | `(Индекс)` → строка; `()` → число; `(Строка)` → позиция или -1 |
| Удалить / Delete, Очистить / Clear, Сдвинуть / Move | `(СтрокаИлиИндекс)`, `()`, `(СтрокаИлиИндекс, Смещение)` |
| Найти / Find | `(Значение[, Колонки])` → первая строка или Неопределено |
| НайтиСтроки / FindRows | `(Отбор)` → Массив исходных строк, в порядке таблицы; Отбор — Структура, все поля должны совпасть |
| Итог / Total | `(ИмяКолонки)` → сумма; в нетипизированной колонке учитываются только числа |
| ВыгрузитьКолонку / UnloadColumn | `(Колонка)` → новый Массив исходных значений |
| ЗагрузитьКолонку / LoadColumn | `(Массив, Колонка)`; короткий массив сохраняет хвост, лишние элементы игнорируются |
| ЗаполнитьЗначения / FillValues | `(Значение[, Колонки])`; допускает Неопределено |
| Скопировать / Copy | `([СтрокиИлиОтбор, Колонки])` → новая таблица |
| СкопироватьКолонки / CopyColumns | `([Колонки])` → новая схема без строк |
| Свернуть / GroupBy | `(КолонкиГруппировки[, КолонкиСуммирования=""])` |
| Сортировать / Sort | `(КолонкиСНаправлением[, ОбъектСравнения])` |

Список колонок — строка имён через запятую, порядок сохраняется. Отсутствующий аргумент, Неопределено или
пустая строка выбирают все колонки. У Copy первый аргумент — Массив строк (сохраняются порядок
и повторы) либо Структура отбора; отсутствие выбирает все строки. Строки другой таблицы с
подходящими именами колонок разрешены, как в 1С. Метаданные колонок копируются; изменяемые
значения ячеек сохраняют общие ссылки. Это обычное поверхностное Copy, не глубокий clone.

GroupBy оставляет колонки группировки/суммирования, объединяет одинаковые ключи и сохраняет
порядок первого появления групп. Пересечение этих двух списков — ошибка. Для отсутствия
группировки передайте `""`; при непустой таблице получится одна итоговая строка. Для отсутствия
суммирования также передайте `""`. Все индексы после GroupBy удаляются.

Коллекция колонок таблицы и дерева поддерживает:

| RU / EN | Аргументы |
|---|---|
| Добавить / Add | `([Имя="", ТипЗначения, Заголовок="", Ширина=0])` |
| Вставить / Insert | `(Индекс[, Имя="", ТипЗначения, Заголовок="", Ширина=0])` |
| Получить / Get, Найти / Find | `(Индекс)`, `(Имя)` → колонка или Неопределено у Find |
| Количество / Count, Индекс / IndexOf | `()`, `(Колонка)` → позиция или -1 |
| Удалить / Delete, Очистить / Clear, Сдвинуть / Move | `(Колонка)`, `()`, `(Колонка, Смещение)` |

Селектор Колонка для удаления/перемещения/ячеек/загрузки — объект колонки, имя или индекс.
`Колонки.Код` и `Колонки["Код"]` дают колонку. Пустые имена допускаются несколько раз, такие
колонки адресуются по индексу/объекту. Непустые имена должны быть идентификаторами и уникальны
без учёта регистра. Повтор имён в Copy/CopyColumns — ошибка, как в 1С.
`Имя/Name`, `Заголовок/Title`, `Ширина/Width` изменяемы; `ТипЗначения/ValueType` readonly.
Переименование/перестановка сохраняют ячейки и индексные определения по identity колонки.
Ширина неотрицательна. Default Title остаётся пустой строкой, как в 1С; OneScript вместо этого
показывает имя колонки. После удаления строка остаётся доступным объектом, но IndexOf даёт -1.

## Описание типов и квалификаторы

`Новый ОписаниеТипов/TypeDescription([Типы, КвалификаторыЧисла, КвалификаторыСтроки, КвалификаторыДаты])`
принимает от 0 до 4 аргументов. Первый — строка имён типов через запятую или Массив объектов Тип;
без него создаётся описание без ограничения типов. Например: `Новый ОписаниеТипов("Число,Строка")`.
Поддерживаются `Типы/Types()`, `СодержитТип/ContainsType(Тип)` и
`ПривестиЗначение/AdjustValue([Значение])`.

Без типов хранится любое значение; типизированные ячейки получают значение по умолчанию
и приводят присваиваемое значение с учётом квалификаторов. Для базовых типов это Число→0,
Строка→`""`, Булево→Ложь, Дата→0001-01-01, UUID→нулевой UUID.
Для составных описаний при выборе значения по умолчанию приоритет: Строка, Булево, Дата, Число, UUID.
Допустимое значение сохраняет свой тип; неудачное преобразование заменяется значением по умолчанию.

`ОписаниеТипов` принимает квалификаторы числа, строки и даты в параметрах 2–4.
Квалификаторы неизменяемы, доступны через одноимённые свойства описания и могут
передаваться фоновым заданиям. `КвалификаторыЧисла(Разрядность=0,ДробнаяЧасть=0,
ДопустимыйЗнак=Любой)` округляют половины от нуля и ограничивают переполнение
максимальным представимым модулем; неотрицательный тип заменяет отрицательное
значение нулём. Нулевая разрядность не ограничивает число.
`КвалификаторыСтроки(Длина=0,ДопустимаяДлина=Переменная)` обрезают по длине;
фиксированная строка дополняется пробелами. Нулевая длина не ограничивает строку.
`КвалификаторыДаты(ЧастиДаты=ДатаВремя)` сохраняют только дату, только время
(с датой 0001-01-01), либо оба компонента. Ограничения применяются как при
`ПривестиЗначение`, так и при присваивании ячейке типизированной колонки.

```bsl
ТипЧисла = Новый ОписаниеТипов("Число", Новый КвалификаторыЧисла(4, 2));
Сообщить(ТипЧисла.ПривестиЗначение(12.345)); // 12.35
```

`Итог/Total` типизированной колонки одного простого типа приводит значения к числу
(включая строки и Булево); нечисловое преобразование сообщает ошибку.
У составного описания без Числа Total возвращает Неопределено.

## Индексы

`Индексы/Indexes` поддерживает `Добавить/Add(ИменаКолонок)`, `Удалить/Delete(ИндексИлиОбъект)`,
`Очистить/Clear()` и `Количество/Count()`. Индекс перебирает имена полей и допускает `[0]`.
Повтор поля в индексе разрешён. При FindRows выбирается самый длинный индекс, полностью
покрытый полями отбора. После первого построения поиск читает подходящую корзину, затем
проверяет оставшиеся поля. Числа в ключах нормализуются без учёта decimal scale.

Любая мутация строк/ячеек/схемы/порядка сразу освобождает кешированные ключи и ссылки на
строки; следующее обращение строит индекс заново. Удалённый индекс тоже освобождает кеш.
Удаление колонки удаляет это поле из индекса, но сохраняет сам индекс, даже пустой. Rename
меняет отображаемое имя поля. Copy/CopyColumns сохраняют только индексы, все поля которых
включены в новую схему; GroupBy очищает индексы. Эти правила следуют 1С: OneScript 2.2.1
теряет индексы при Copy и оставляет определения при GroupBy.

## Список значений

Список перебирает элементы, `[Индекс]` и `Получить/Get(Индекс)` дают элемент.
Свойства списка `ТипЗначения/ValueType` (ОписаниеТипов) и `ДоступныеЗначения/AvailableValues`
(СписокЗначений либо Неопределено) изменяемы. Они применяются к новым и присваиваемым значениям,
не преобразуют уже сохранённые элементы. При заданном типе значение вне AvailableValues
заменяется default типа.

| RU / EN | Аргументы и результат |
|---|---|
| Добавить / Add | `([Значение=Неопределено, Представление="", Пометка=Ложь, Картинка])` → элемент |
| Вставить / Insert | `(Индекс[, те же четыре аргумента])` → элемент |
| Количество / Count, Индекс / IndexOf | `()`, `(Элемент)` → позиция или -1 |
| Удалить / Delete, Очистить / Clear, Сдвинуть / Move | `(ЭлементИлиИндекс)`, `()`, `(ЭлементИлиИндекс, Смещение)` |
| НайтиПоЗначению / FindByValue | `(Значение)` → первый элемент или Неопределено |
| НайтиПоИдентификатору / FindByID | `(Число)` → элемент или Неопределено; метод 1С, отсутствует в OS 2.2.1 |
| ВыгрузитьЗначения / UnloadValues, ЗагрузитьЗначения / LoadValues | `()` → новый Массив; `(Массив)` заменяет элементы |
| ЗаполнитьПометки / FillChecks | `(Булево)` |
| Скопировать / Copy | `()` → независимые элементы, общие ссылки на их значения |
| СортироватьПоЗначению / SortByValue, СортироватьПоПредставлению / SortByPresentation | `([Направление=НаправлениеСортировки.Возр])` |

Свойства элемента `Значение/Value`, `Представление/Presentation`, `Пометка/Check`, `Картинка/Picture`
изменяемы. `ПолучитьИдентификатор/GetID()` возвращает число, независимое от позиции.
ID сохраняется после Copy и перемещения; новые элементы после Clear/LoadValues получают новые ID.
Строковое представление элемента использует Presentation, а при пустом Presentation — Строка(Value).
Picture хранится как непрозрачное значение, default Неопределено, как в OS; графический тип
Картинка, библиотеки картинок и ФорматированнаяСтрока не реализованы. Диалоги ChooseItem,
CheckItems/ОтметитьЭлементы и другие UI/async методы отсутствуют.

## Дерево значений

У дерева readonly `Колонки/Columns`, `Строки/Rows`. `Скопировать/Copy()` копирует всю структуру
со схемой и поверхностными значениями ячеек; лишние аргументы — ошибка, как в 1С.
OS 2.2.1 молча игнорирует аргумент Copy с массивом строк; juno этот баг не повторяет.

Строка дерева имеет readonly `Родитель/Parent` (Неопределено у корня), `Строки/Rows`, методы
`Владелец/Owner()` → дерево, `Уровень/Level()` → 0 у корня и `Получить/Get(Индекс)`,
`Установить/Set(Индекс, Значение)`. Ячейки и перебор работают как у строки таблицы.
У коллекции строк readonly `Родитель/Parent` — владеющая строка либо Неопределено у корня.

| RU / EN | Аргументы |
|---|---|
| Добавить / Add, Вставить / Insert, Получить / Get | `()`, `(Индекс)`, `(Индекс)` |
| Количество / Count, Индекс / IndexOf | `()`, `(Строка)` |
| Удалить / Delete, Очистить / Clear, Сдвинуть / Move | `(СтрокаИлиИндекс)`, `()`, `(СтрокаИлиИндекс, Смещение)` |
| Найти / Find | `(Значение[, Колонки, ВключатьПодчинённые=Ложь])` |
| НайтиСтроки / FindRows | `(СтруктураОтбора[, ВключатьПодчинённые=Ложь])` |
| Итог / Total | `(Колонка[, ВключатьПодчинённые=Ложь])` |
| ЗагрузитьКолонку / LoadColumn, ВыгрузитьКолонку / UnloadColumn | `(Массив, Колонка)`, `(Колонка)`; только строки текущей коллекции |
| Сортировать / Sort | `(КолонкиСНаправлением[, ВключатьПодчинённые=Ложь, ОбъектСравнения])` |

Find/FindRows с подчинёнными обходят дерево в глубину, родитель перед детьми. Total с
подчинёнными суммирует все посещённые строки, включая промежуточные. Sort с подчинёнными
сортирует каждую коллекцию строк одного родителя отдельно. Плоского перемещения между родителями нет.

## Изменение коллекции во время `Для Каждого`

`Массив`, `СписокЗначений`, `ТаблицаЗначений`, строки дерева и коллекции колонок обходятся по позиции, и размер
проверяется на каждом шаге — как в 1С 8.3.27.1606: добавленные элементы посещаются (удобно для очереди),
после удаления текущего элемента следующий пропускается, `Очистить` завершает цикл, `Сортировать` в цикле
переставляет строки под курсором, `Вставить` в начало зацикливает обход. Ошибки модификации нет.
`Структура` и `Соответствие` обходятся по снимку ключей: добавленные в цикле ключи не посещаются, удалённые
всё равно посещаются. Порядок обхода `Соответствия` в 1С не определён; juno обходит в порядке вставки.

## Сортировка, перенос и пример

Строка сортировки: `"Код Возр,Сумма Убыв"` или `"Code Asc,Amount Desc"`. Все имена проверяются
до сортировки, даже для пустой коллекции. Применяется стабильная сортировка. Строки сравниваются
словарным порядком 1С без учёта регистра (`StringOrder`, см. [значения](values.md)): `е` предшествует `ё`,
пробел и знаки меньше цифр и букв. Порядок равных строк разного регистра в 1С не определён (она их
не сохраняет), juno оставляет их в исходном порядке. `СортироватьПоПредставлению` у списка значений
использует полный порядок с учётом регистра по сохранённому представлению, пустое идёт первым.
OneScript может менять порядок равных строк. Полная эквивалентность Unicode/collation ICU/.NET не обещается.
Для разнородных базовых типов порядок: Неопределено, Null, Булево, Число, Дата, Строка;
остальные объекты сравниваются по строковому представлению.
`Новый СравнениеЗначений/CompareValues` без аргументов предоставляет `Сравнить/Compare(А, Б)`
→ -1/0/1 с теми же правилами и принимается Table/Tree.Sort. НаправлениеСортировки/SortDirection
содержит `Возр/Asc`, `Убыв/Desc`.

Фоновые задания получают глубокий snapshot: таблицы, индексы, списки, деревья, строки и
колонки копируются с сохранением циклов и общих ссылок. Перестановки колонок, отдельные
ссылки на удалённые строки и вложенные коллекции строк поддерживаются. Кеш индекса не переносится.
Обычные Copy/CopyColumns остаются поверхностными.

Рабочий пример: `juno run examples/коллекции/Программа.bsl`.
Он группирует продажи, ищет через индекс, строит список представлений и дерево деталей.
