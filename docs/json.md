# Публичный JSON для BSL

API работает на JDK 21 без зависимостей. Это отдельная реализация от строгого внутреннего
`juno.Json`, читающего настройки CLI: комментарии в `juno.json` не разрешены.
Различия с OneScript 2.2.1 и 1С 8.3.27.1606 указаны для соответствующих операций.

## Чтение

`Новый ЧтениеJSON` / `Новый JSONReader` — без аргументов.

| Метод RU / EN | Поддержанные аргументы / результат |
|---|---|
| `УстановитьСтроку` / `SetString` | `(Текст)` |
| `ОткрытьФайл` / `OpenFile` | `(Путь, Кодировка = "UTF-8")` |
| `Прочитать` / `Read` | `()` → Булево; false на EOF |
| `Пропустить` / `Skip` | `()` → Булево; см. cursor ниже |
| `Закрыть` / `Close` | `()`; идемпотентно, источник можно задать заново |

Кодировка файла — имя кодировки строкой, не enum `КодировкаТекста`; пустая строка/Неопределено
выбирает UTF-8. BOM UTF-8/UTF-16LE/BE снимается и определяет фактическую кодировку.
Относительный путь разрешается через виртуальный cwd приложения. Поддержаны обычные файлы,
без FIFO/устройств/каталогов. Файл читается BufferedReader по частям, без readAll/readAllBytes.
Некорректные bytes вызывают ошибку декодера.

Readonly свойства:

- `ТипТекущегоЗначения` / `CurrentValueType`: `ТипЗначенияJSON` / `JSONValueType`.
- `ТекущееЗначение` / `CurrentValue`: строка/BigDecimal/Булево/**Null**; у None/границ контейнеров — ошибка.
- `ТекущаяСтрока` / `CurrentLine`, `ТекущаяПозиция` / `CurrentPosition`: позиция **после** token,
  строки с 1, позиция в UTF-16 code units; до первого Read — 0/0.

`JSONValueType` содержит `Ничего/None`, `Null`, `Булево/Boolean`, `ИмяСвойства/PropertyName`,
`Комментарий/Comment`, `КонецМассива/ArrayEnd`, `КонецОбъекта/ObjectEnd`,
`НачалоМассива/ArrayStart`, `НачалоОбъекта/ObjectStart`, `Строка/String`, `Число/Number`.
PropertyName потребляет двоеточие; его value — имя. По умолчанию разрешены `//` и `/*...*/`:
Read выдаёт Comment token с текстом без delimiters. Комментарии между именем и двоеточием
принимаются как разделители, отдельным token в этой позиции не выдаются.

Skip на ObjectStart/ArrayStart проходит контейнер **и его конец**, затем читает уже следующий
sibling token (либо EOF); на прочих tokens работает как Read. EOF стабилен: false, тип None,
позиция конца. У закрытого/unopened reader line/position — Неопределено, type/value/Read — ошибка.

`ПрочитатьJSON(Чтение, ВСоответствие = Ложь, ИменаСвойствДат = Неопределено,
ФорматДат = Неопределено)` / `ReadJSON` сначала вызывает **следующий Read**
и читает одно значение. Поэтому после ручного Read на ArrayStart он читает первый элемент,
а после текущего PropertyName — его значение. Возвращает изменяемые Массив/Структура;
при `ВСоответствие = Истина` все JSON-объекты становятся Соответствием.

Как в 1С 8.3.27.1606, `ПрочитатьJSON` отвергает комментарии перед значением и внутри него.
Комментарии в хвосте прочитанного корня разрешены. При ручном обходе токенов
`ЧтениеJSON.Прочитать()` комментарии возвращаются как Comment.

При чтении root немедленно проверяется хвост: whitespace/comments разрешены, второе значение
или мусор — ошибка. Cursor остаётся на последнем token возвращённого значения с его логической
позицией; следующий Read показывает EOF с фактической конечной позицией. Вложенное чтение
после PropertyName/в массиве хвост всего документа не проверяет.

Повторяющийся ключ заменяет предыдущее значение. Структура сравнивает имена без регистра;
имя — Unicode-буква/`_`, далее буквы/цифры/`_`, включая слова `Истина` и т.п.
Пустой ключ или `a-b` в Структуре — ошибка; Соответствие допускает любые JSON string keys.
JSON `null` превращается в **языковой Null**, отдельно от Неопределено. Это осознанное отличие:
OneScript 2.2.1 ReadJSON/CurrentValue возвращает для null Неопределено.

Числа читаются напрямую в BigDecimal, без double и локализованного разбора. В OneScript 2.2.1
большое дробное число теряло точность — juno сохраняет её. Только JSON-грамматика: ASCII digits,
без ведущего `+`, leading zeros, NaN/Infinity, trailing comma, single quotes/unquoted keys,
invalid escapes, control chars и непарных surrogate. Ошибки содержат строку/позицию.

## Запись

`Новый ЗаписьJSON` / `Новый JSONWriter` — без аргументов.

| Метод RU / EN | Поддержанные аргументы |
|---|---|
| `УстановитьСтроку` / `SetString` | `(Параметры = Неопределено)` |
| `ОткрытьФайл` / `OpenFile` | `(Путь, Кодировка = "UTF-8", ДобавитьBOM = Ложь, Параметры = Неопределено)` |
| `ЗаписатьНачалоОбъекта` / `WriteStartObject` | `()` |
| `ЗаписатьКонецОбъекта` / `WriteEndObject` | `()` |
| `ЗаписатьНачалоМассива` / `WriteStartArray` | `()` |
| `ЗаписатьКонецМассива` / `WriteEndArray` | `()` |
| `ЗаписатьИмяСвойства` / `WritePropertyName` | `(Имя)` — строка |
| `ЗаписатьЗначение` / `WriteValue` | `(Значение, ЭкспоненциальныйФормат = Ложь)`; true явно не поддерживается |
| `ЗаписатьБезОбработки` / `WriteRaw` | `(Текст)` — проверяется как одно полное значение, без комментариев |
| `Закрыть` / `Close` | `()` → строка для SetString; `""` для файла/повторного Close |

WriteValue принимает примитивы: String, BigDecimal, Boolean, Null, Неопределено (оба последних → null).
Десятичная точка без группировки/экспоненты; завершающие нули могут убираться, числовое значение сохраняется.
Writer проверяет names/values, согласованные контейнеры, один root и завершённый непустой документ.
После Close дальнейшая запись — ошибка, до нового SetString/OpenFile.
`ПроверятьСтруктуру` / `ValidateStructure` остаётся true, попытка отключить — явная ошибка.
`Параметры` / `Settings` — readonly текущие настройки.

`ЗаписатьJSON(Запись, Значение)` / `WriteJSON` рекурсивно пишет примитивы, Структуру,
Соответствие, Массив и их фиксированные варианты. Цикл — ошибка; повторное использование одной
ссылки без цикла допускается. Ключи Соответствия должны быть строками, как в 1С;
Числовой, булев и любой другой нестроковый ключ — ошибка.
Произвольные типы, включая таблицы/потоки/Type, не сериализуются молча.

Default файла — UTF-8 **без BOM**, без добавочного EOL. `ДобавитьBOM = Истина` пишет выбранный
UTF-8/UTF-16 preamble. Файл открывается с перезаписью, ошибки могут оставлять частичный файл;
атомарной замены здесь нет. WriteRaw в juno проверяет корректность JSON: `{bad}`/второй root
не проходят. WriteRaw участвует в writer state, а не обходит его.

## Параметры и даты

`Новый ПараметрыЗаписиJSON` / `JSONWriterSettings` принимает optional args в порядке:

1. `ПереносСтрок/NewLines = JSONLineBreak.Auto`: Auto/Unix/Windows/None (`Авто/Нет`).
2. `СимволыОтступа/PaddingSymbols = ""`: до 256 пробелов/табуляций, вся строка повторяется по depth.
3. `ИспользоватьДвойныеКавычки/UseDoubleQuotes = Истина`: false отвергается.
4. `ЭкранированиеСимволов/EscapeCharacters = JSONCharactersEscapeMode.None`:
   `None/Нет`, `NotASCIISymbols/СимволыВнеASCII`, `SymbolsNotInBMP/СимволыВнеBMP`.
5. `ЭкранироватьУгловыеСкобки/EscapeAngleBrackets = Ложь`.
6. `ЭкранироватьРазделителиСтрок/EscapeLineTerminators = Истина` (U+2028/U+2029).
7. `ЭкранироватьАмперсанд/EscapeAmpersand = Ложь`.
8. `ЭкранироватьОдинарныеКавычки/EscapeSingleQuotes = Ложь`.
9. `ЭкранироватьСлеш/EscapeSlash = Ложь`.

Эти свойства readonly. В default Auto используется native EOL, отступ пуст; None даёт компактный
JSON. Для машинных протоколов выбирайте None. Отступ из двух пробелов применяется как два пробела;
OneScript 2.2.1 использует один символ — побайтовое совпадение whitespace не обещается.

Даты пишутся и читаются как в 1С 8.3.27.1606. `ЗаписатьJSON(Запись, Дата)` без настроек пишет локальную дату
ISO строкой `"2024-02-29T10:00:05"` (пустая дата — `"0001-01-01T00:00:00"`), в том числе внутри структур,
массивов и соответствий. Формат и вариант задаёт `НастройкиСериализацииJSON/JSONSerializerSettings`
(третий аргумент `ЗаписатьJSON`) со свойствами `ФорматСериализацииДаты/DateSerializationFormat` (по умолчанию ISO) и
`ВариантЗаписиДаты/DateWritingVariant` (по умолчанию `ЛокальнаяДата/LocalDate`).

```bsl
Текст = ЗаписатьДатуJSON(Дата(2024,2,29,10,0,5), ФорматДатыJSON.ISO);                                    // 2024-02-29T10:00:05
Текст = ЗаписатьДатуJSON(Д, ФорматДатыJSON.ISO, ВариантЗаписиДатыJSON.ЛокальнаяДатаСоСмещением);         // ...+03:00
Текст = ЗаписатьДатуJSON(Д, ФорматДатыJSON.ISO, ВариантЗаписиДатыJSON.УниверсальнаяДата);                // 2024-02-29T07:00:05Z
Текст = ЗаписатьДатуJSON(Д, ФорматДатыJSON.JavaScript, ВариантЗаписиДатыJSON.УниверсальнаяДата);         // new Date(1709190005000)
Текст = ЗаписатьДатуJSON(Д, ФорматДатыJSON.Microsoft, ВариантЗаписиДатыJSON.УниверсальнаяДата);          // /Date(1709190005000)/
Д = ПрочитатьДатуJSON(Текст, ФорматДатыJSON.ISO);
```

Формат `JavaScript` и `Microsoft` доступен только с `УниверсальнаяДата`; локальную дату записать в них нельзя
(«Невозможно сохранить локальную дату в формате JavaScript»), как в 1С. Пустая дата при записи не сдвигается
(`0001-01-01T00:00:00Z`, смещение `+00:00`). Часовой пояс — системный, как у платформы; дата с долями секунды
отвергается, чтобы не терять точность.

`ПрочитатьДатуJSON(Строка, Формат)` (оба аргумента обязательны) читает ISO гибко, как платформа: дата
`yyyy-MM-dd` или `yyyyMMdd`, время `T HH`, `HH:mm`, `HH:mm:ss` с долями секунды (они отбрасываются), зона
(`Z`, `±HH`, `±HH:mm`, `±HHmm`, до ±24:00) допустима только после секунд. Время с зоной переводится в
местное; результат ограничен диапазоном 0001-01-01..9999-12-31 (`9999-12-31T23:59:59Z` остаётся последней датой).
Пробелы по краям и перед зоной допускаются; регистр `t`/`z`, год `0000`, несуществующие даты, `24:00:00`,
секунда 60 и однозначные компоненты отвергаются с текстом `Представление даты имеет неверный формат ('...')`.
Единственное известное расхождение: бессмысленное смещение `+03:60` платформа принимает, juno отвергает.
`JavaScript` читает `new Date(мс)`, `Microsoft` — `/Date(мс)/` (со смещением в 1С — ошибка); значение
переводится в местное время.

`ПрочитатьJSON(Чтение, ВСоответствие, ИменаСвойствДат, ФорматДат)`: имена — строка или массив строк, формат
по умолчанию ISO. Свойство `Null` остаётся `Null`; пустая строка и неверный текст — ошибка. Функции
преобразования и восстановления отвергаются, не игнорируются.

## Фиксированные коллекции и ресурсы

`Новый FixedArray(Массив)` и `Новый FixedMap(Соответствие)` делают **shallow snapshots**:
изменение внешнего источника не меняет snapshot, вложенные значения сохраняют ссылки.
`Новый Array(FixedArray)` / `Новый Map(FixedMap)` возвращают изменяемую shallow copy.
Fixed constructors требуют один изменяемый источник; Map(Map), FixedArray(FixedArray),
FixedMap(FixedMap) не являются альтернативами копирования. FixedStructure принимает строку имён и значения либо создаёт snapshot Структуры. Type aliases и Строка возвращают канонические RU имена.

Массив/FixedArray: Count, UBound, Find (нет → Неопределено), Get и индекс; у mutable также Set
и Add/Insert/Delete/Clear. Map/FixedMap: Count/Get/индекс/перебор; изменения FixedMap запрещены через методы, свойства и индексы. Вложенные mutable значения
не становятся readonly. ValueCopy сохраняет fixed type, алиасы и циклы, глубоко копируя граф для задания.

Reader/Writer требуют ApplicationContext (в Java — `Execution.withContext`) и принадлежат scope.
Явный Close полезен для предсказуемого времени жизни. EOF/root ReadJSON освобождает файл,
ошибка разбора/сериализации — тоже; logical cursor можно читать до Close. Выход scope закрывает
каналы и flush завершённого writer; незавершённый документ даёт ошибку cleanup, канал всё равно закрыт.
Отмена закрывает FileChannel вне блокировки Reader/Writer, buffered хвост может быть потерян.
Открытые JSON-объекты не передаются ValueCopy; immutable writer settings можно передавать.

Границы безопасности **этого JSON API**, без изменения глобальной арифметики: 256 вложенных
контейнеров; токен/строка до 1 048 576 UTF-16 units; |BigDecimal scale| ≤100 000 и длина plain
numeric output до 1 048 576. Ограничение отступа описано выше. Токены обрабатываются частями,
но один token занимает память пропорционально длине; ReadJSON целиком материализует значение.

## Пример конфигурации и JSONL

```sh
printf '{"value":1}\nnull\n' | java -jar build/juno.jar run examples/json/Программа.bsl examples/json/Настройки.json
java -jar build/juno.jar build examples/json/Программа.bsl --output jsonl.jar
printf '[1,2]\n' | java -jar jsonl.jar examples/json/Настройки.json
```

[Программа](../examples/json/Программа.bsl) читает JSON-файл с явным ISO property,
затем по одному JSON value на строку stdin и пишет компактный JSONL, сохраняя точную дробь.
Пустая строка ввода — ошибка JSON, EOF завершает обработку. Ошибка идёт в stderr с exit3;
успех — exit0; служебные сообщения не попадают в stdout.
