# Реестр модулей

`Модули` / `Modules` — глобальное свойство juno, предоставляющее общий экземпляр
каждого модуля в текущем контексте выполнения. Это расширение juno для объектных BSL-модулей.

| RU / EN | Аргументы и результат |
|---|---|
| `Получить` / `Get` | `(Имя)` → общий объект модуля; неизвестное имя вызывает ошибку |
| `Содержит` / `Contains` | `(Имя)` → Булево: входит ли модуль в собранную программу |
| `Имена` / `Names` | `()` → ФиксированныйМассив полных имён модулей |

Имя — строка с полным именем, включая пространство имён библиотеки или подпапки:
`"Логирование"`, `"Сервисы.Почта"`, `"Shared.Настройки"`. Регистр не учитывается,
пробелы не обрезаются. `Имена()` возвращает канонические имена в порядке их строк,
приведённых к нижнему регистру; результат нельзя изменять. Служебный парсер runtime
в этот список не входит.

`Содержит` и `Имена` не создают экземпляры и не выполняют тело модуля.
Объект реестра имеет тип `Модули` / `Modules`; конструктор `Новый Модули` не поддерживается.

## Общий экземпляр

```bsl
Лог = Модули.Получить("Логирование");
Лог.Записать("Начало работы");

ТотЖеЛог = Modules.Get("ЛОГИРОВАНИЕ");
ТотЖеЛог.Записать("Продолжение работы");
```

При первом `Получить` выполняется тело модуля, затем `ПриСозданииОбъекта()` без аргументов.
Параметры конструктора могут иметь значения по умолчанию; обязательные параметры вызывают ошибку.
После успешной инициализации реестр сохраняет объект. Все обращения в этом контексте
возвращают его же, поэтому состояние экспортных переменных сохраняется между вызовами.
Доступ к методам и переменным подчиняется обычным правилам `Экспорт`.

`Новый Логирование` создаёт независимый объект и не заменяет общий экземпляр.
Вызов `Логирование.Записать()` непосредственно через имя класса не поддерживается:
сначала получите объект через реестр или `Новый`.

Неуспешная инициализация не сохраняет объект; следующее обращение может повторить её.
Действия, выполненные до ошибки, не откатываются. При цикле инициализации ошибка
показывает цепочку, например `Настройки → Логирование → Настройки`; частично созданный
объект не возвращается.

## Время жизни и изоляция

Кеш хранится в runtime и принадлежит текущему контексту выполнения:

- один набор общих экземпляров на запуск программы;
- отдельный набор для каждого теста;
- отдельный набор для каждого фонового задания, без копирования кеша родителя.

Завершение контекста освобождает его кеш и закрывает принадлежащие ему ресурсы runtime.
Пользовательские методы `Закрыть()` автоматически не вызываются.
Сам реестр нельзя передавать в параметры или результаты фонового задания. Внутри задания
используйте его собственное глобальное свойство `Модули`.

## Состав программы

Реестр содержит только модули, включённые в сборку. Он не сканирует файловую систему
при обращении и не загружает дополнительные файлы.

В проекте с `schemaVersion: 1` модули задаются через `sources` и локальные `dependencies`.
Их имена можно вычислять во время выполнения:

```bsl
Имя = "Shared." + "Настройки";
Настройки = Модули.Получить(Имя);
```

При запуске отдельного скрипта без `schemaVersion` сборщик включает модули, чьи полные
имена упомянуты в исходниках, в том числе в строке `Модули.Получить("Логирование")`.
Вычисляемое имя само по себе не добавляет модуль в такую сборку. Для обнаружения всех
модулей через `Имена()` задайте состав проекта явно в [manifest](projects.md).

Пример: [examples/модули](../examples/модули).
